回传阶段是设备数据回到活字格的入口。现场作业人员恢复网络后，通过 HAC 打开活字格上传页面，页面使用“上传离线表单”命令读取设备项目、导出填报记录、上传附件，并在确认入库后标记或清理设备数据。

## 命令总览

命令名称：**上传离线表单**。

作用：为活字格页面提供设备端离线数据的回传与维护能力，包括读取设备上的离线表单项目、导出填报记录、回传本地附件、标记记录已导出以及清理离线数据。开发者只需在设计器中按业务场景选择一项能力并配置参数，插件会负责完成与 HAC 的通信和附件上传。

命令在设计器中提供以下能力：

| 能力 | 使用场景 | 需要配置 | 返回内容 |
| --- | --- | --- | --- |
| 获取设备上的离线表单项目编号列表 | 在页面上展示设备当前保存的离线表单项目，供用户选择回传范围 | 无需项目编号 | 项目编号列表 |
| 导出离线表单数据 | 回传指定离线表单项目下的填报记录，并处理记录中的图片与文件 | 项目编号 | 导出结果 |
| 批量导出离线表单数据 | 一次回传设备上多个离线表单项目的填报记录 | 无需项目编号 | 导出结果 |
| 标记离线记录已导出 | 服务端确认入库成功后，把对应记录标记为已导出 | 项目编号、记录编号 | 操作结果 |
| 删除已读离线记录 | 清理已确认安全回传的已读记录 | 项目编号，记录编号可选 | 操作结果 |
| 删除离线表单项目 | 整个离线表单项目不再需要时，从设备清理该项目 | 项目编号 | 操作结果 |

## 参数说明

| 参数 | 说明 |
| --- | --- |
| 项目编号 | 目标离线表单项目，与 Pattern 根字段 `patternId` 一致。 |
| 记录编号 | 用于标记或删除指定记录；多个记录编号使用英文逗号分隔，例如 `record1,record2`。 |
| 项目编号列表 | “获取设备上的离线表单项目编号列表”返回的内容。 |
| 导出结果 | 导出或批量导出返回的离线记录数据。 |
| 操作结果 | 标记记录、删除记录或删除项目返回的操作结果。 |

记录编号规则如下：

- “标记离线记录已导出”的记录编号必填。
- “删除已读离线记录”填写记录编号时只删除指定已读记录；不填写时删除该项目下全部已读记录。
- 其他能力不使用记录编号。

## 推荐的设备数据处理顺序

设备上的数据不能只“上传成功”就删除，必须以活字格服务端确认入库为准。建议按以下顺序处理：

1. 先导出并完成服务端入库。
2. 入库成功后，再标记记录已导出。
3. 只有确认数据已安全落库后，才删除已读记录或整个项目，避免离线数据丢失。

删除时机总结：

- 单条记录确认安全后，可“删除已读离线记录”并按需传入该记录编号。
- 多条记录都安全后，可不传记录编号，清理该项目下全部已读记录。
- 整个表单项目确认不再需要时，再“删除离线表单项目”。

<Callout type="warn">
设备本地的 `status` 只反映 HAC 侧状态，例如“待上传”“已读”。一条记录是否真的进入业务库，要以活字格写表结果为准，不应把设备状态当作入库凭证。
</Callout>

## 导出结果的后续使用

“导出离线表单数据”和“批量导出离线表单数据”返回的“导出结果”会交给活字格变量，通常由服务端命令继续解析和写表。不同回传方式的返回结构略有差异：

- 单项目导出：返回 `{ records: [...] }`，项目编号通过命令参数传入。
- 批量导出：返回项目对象数组，不需要填项目编号。

具体结构见[导出结果](/docs/solutions/offline-form/export-result)，从结果到业务表的完整处理见[服务端解析与写表](/docs/solutions/offline-form/server-parse)。
