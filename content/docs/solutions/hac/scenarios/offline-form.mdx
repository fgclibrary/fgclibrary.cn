可以想象一个很常见的现场：人已经到了，设备也准备好了，检查、验收或维修必须马上开始，可在线表单一直转圈，或者打开之后很快又断了。

最后，现场人员往往只能拿纸笔记下来，拍几张照片发到群里，回到办公室再重新整理。等到录入系统时，可能已经记不清照片对应哪一项，手写记录也可能漏掉关键内容。**现场工作完成了，数据却还要重新“做一遍”。**

HAC 离线填报就是为这样的现场准备的。它把活字格的表单能力延伸到断网现场，工作方式可以概括为一句话：

> **在线准备任务，离线完成工作，联网完成闭环。**

![HAC 离线填报：一项现场任务的完整流转](/images/hac/offline-form-flow.svg)

## 方案怎么工作

1. 有网络时，管理者在活字格中准备现场任务：任务名称、作业步骤、检查要求、必填项、照片、文件、签名和明细列表，提前配置好并下发到 HAC 设备；
2. 到达现场后，即使网络变差甚至完全中断，工作人员仍可打开已下发的任务，按标准完成填报、拍照、附加资料、填写多条明细，最后签名提交；
3. 填报记录和附件先保存在设备本地；网络恢复后再回到活字格，完成业务入库和资料归档。

## 业务价值

### 让现场工作持续进行

网络不稳定时，工作人员不必停下来等信号，也不必在几种临时记录工具之间来回切换。任务已经在设备上，工作就可以按计划继续。

这对巡检、验收、盘点、普查、维修等工作尤其重要：它们通常有明确的时间窗口，人员已经到位，错过一次作业就可能增加调度、交通和协调成本。

### 让现场记录更完整

一项现场工作经常同时需要文字、选项、时间、照片、文件和签名，离线表单可以把这些内容放在同一条任务记录里。

以设备巡检为例：人员先填写设备和任务信息，再逐项判定“合格 / 不合格”，对异常情况新增问题明细，拍下现场照片，最后由巡检人员完成签名。回传时文字和附件仍然围绕同一条记录组织，后续查找与追溯都会轻松很多。

### 让现场人员按标准做事

纸笔记录很依赖个人经验：检查哪些项目、哪些内容要拍照、哪些字段必须填写，容易因人员不同而产生差异。

离线表单可以把作业步骤、分组、说明文字、必填规则和进度提示提前放进去。新员工也能按表单走完整流程，经验丰富的人员则可以更快完成任务，管理者得到的是更统一的过程数据。

### 让表单跟随业务变化

现场业务很少只有一种固定格式：巡检关注“是否合格”，工程验收关注“验收标准”和“问题清单”，客户服务还需要“处理过程”“替换物料”和“客户签字”。

离线表单把表单设计做成了可组合的能力——多个步骤、分组与进度、说明文本与说明 PDF，以及文本框、密码框、下拉选择、单选、日期时间、图片、文件、签名和可新增的明细列表。表单项目支持编号和版本管理，要求变化时调整表单定义即可，不必为每种变化重新开发一套移动端程序。

## 典型场景

| 场景 | 现场要完成的事 |
| --- | --- |
| 设备巡检 | 逐项记录检查结果、异常明细与照片，离开现场前完成签名。 |
| 工程验收 | 核对验收标准、记录问题清单，补充照片与签字。 |
| 普查、盘点与现场调查 | 在园区、仓库或偏远区域逐点采集，用明细列表记录多条结果。 |
| 维修与客户服务 | 记录故障现象、处理过程与替换物料，请客户签名确认。 |
| 应急处置 | 在受影响网络中记录现场状态、处置措施与证据资料，恢复后集中回传。 |

## 技术设计要点

这套方案把「传输与暂存」和「业务规则」分开：HAC 负责在设备本地渲染表单、保存记录与附件；表单定义的下发、数据回传和业务入库仍由活字格侧完成。

### 数据如何流转

| 环节 | 载体 | 关键标识 |
| --- | --- | --- |
| 下发任务 | Pattern JSON（表单项目） | `patternId` |
| 现场填报 | 设备本地记录与附件 | `recordId` |
| 回传结果 | ExportResult JSON | 字段 `itemId` |
| 业务入库 | 活字格业务数据表 | 业务主键 |

### 业务页面仍需自行设计

HAC 是通用能力的容器，不包含具体业务。以下四项属于业务规则，需要由业务页面设计：

- **业务主键**：为每条记录定义可追溯的业务标识，回传后才能对应到正确的业务对象；
- **幂等提交**：重复回传或重复点击不应生成重复的业务记录；
- **补传**：网络恢复后能按范围重新导出并提交尚未完成的数据；
- **冲突处理**：同一单据被多人、多机修改时，明确以哪一份为准。

<Callout type="warn">
附件上传后默认位于活字格服务器的**附件临时目录**，只有后续写表操作完成，附件才会被正式回写并归属到业务记录。

“导出完成”只表示数据已经离开设备，**并不代表业务入库已经完成**；确认数据安全入库后，设备上的记录才适合清理。
</Callout>
