HAC 通过插件命令向活字格页面开放一组设备能力。这些能力可以先单独使用，再按现场任务组合成完整流程。本页先说明有哪些基础能力，再说明它们能支撑哪些场景。

## 基础能力

| 能力 | 能做什么 | 说明页 |
| --- | --- | --- |
| 扫描 | 接收激光 / 二维扫描头或 UHF / RFID 的读取结果 | [扫描](/docs/solutions/hac/features/scanner) |
| 定位 | 读取设备当前位置的经纬度 | [定位](/docs/solutions/hac/features/gps-location-demo) |
| 读取 NFC 标签 | 靠近标签读取其唯一标识 | [读取 NFC 标签](/docs/solutions/hac/features/nfc-tag-reading) |
| BLE 设备读写 | 扫描附近低功耗蓝牙设备，读取、订阅或写入数据 | [BLE 设备读写](/docs/solutions/hac/features/ble-device) |
| 生物识别认证 | 调用系统指纹、人脸或设备密码完成二次确认 | [生物识别认证](/docs/solutions/hac/features/biometric-authentication) |
| 拍摄 | 拍照、录像、录音，添加水印并读取本地文件 | [拍摄](/docs/solutions/hac/features/camera-capture) |
| 离线存储 | 断网时把键值数据暂存在设备本地 | [离线模式](/docs/solutions/hac/features/offline-model-hac) |
| APP 交互 | 打开原生页、预览 PDF、拨号、震动、提示音与广播 | [APP 交互](/docs/solutions/hac/features/app-interaction) |
| 物理按键监听 | 把实体按键接到页面动作上 | [物理按键监听](/docs/solutions/hac/features/physical-key-listening) |

除设备能力外，还可以通过[个性化配置](/docs/solutions/hac/installation/app-personalization)调整 ActionBar、菜单与扫描头参数。按命令名称查找对应说明页时，见[插件功能列表](/docs/solutions/hac/features/command-index)。

## 能支撑哪些场景

把上面的能力组合起来，可以覆盖多种现场作业。下表的“常用能力”指这类场景最主要的依赖。

| 场景 | 常用能力 | 现场做什么 |
| --- | --- | --- |
| 收货、拣货、复核 | 扫描 | 扫单据与物料，核对品种与数量 |
| 资产盘点、托盘识别 | 扫描（UHF / RFID） | 批量读取标签，去重后匹配业务对象 |
| 设备巡检、工位确认 | 扫描、NFC | 靠近标签确认当前对象，再逐项检查 |
| 现场签到、巡检打卡 | 定位 | 记录人员到岗位置与时间 |
| 拍照取证、入库验收 | 拍摄 | 拍摄照片、录像或录音，必要时加水印 |
| 传感器采集、设备控制 | BLE | 读取或订阅周边设备数据，必要时下发指令 |
| 作废、放行、高价值出入库 | 生物识别认证 | 由当前操作人完成二次确认 |
| 戴手套、单手连续作业 | 物理按键监听 | 用实体按键代替触屏完成高频动作 |
| 弱网、无网现场作业 | 离线存储 | 先暂存本地，网络恢复后再提交 |

## 能力如何组合

单条命令通常只解决一个动作，现场作业往往需要把多项能力串成流程。例如一次收货，可能是“扫码核对 + 拍照留痕 + 弱网暂存 + 联网回传”。

这类完整流程的组织方式，可参考[离线填报](/docs/solutions/hac/scenarios/offline-form)。

## 使用边界

- 持续扫码、广播接收、BLE 订阅和物理按键监听离开页面时必须停止；
- 页面必须区分“本地已保存”“待补传”和“已提交到服务端”；
- 配置类操作放在运维或管理员入口，普通操作员只看到业务流程；
- 普通浏览器无法调用 HAC 的 Android 能力，应隐藏入口或明确提示运行环境。

页面布局、触控和性能原则见[原则与最佳实践](/docs/solutions/hac/principles)。
