交互行为要让用户知道：**现在能做什么，操作后发生什么，出错后如何继续**。常用动作直接完成，需要判断时再确认。

## 设计原则与最佳实践

1. **入口与动作对应。** 用“保存修改”“接收货品”等具体文案，区分数量编辑和业务接收。
2. **减少重复输入。** 用扫码、筛选和数量加减加快操作；数量变化较大时，按业务需要提供直接输入。
3. **每次操作都有反馈。** 处理中可识别，保存后回显数量，校验失败说明原因和下一步。
4. **失败保留数据。** 保留当前订单、物料和输入，允许修正或重试。提交超时先确认结果，避免重复提交。
5. **切换不丢状态。** 关闭面板、返回或切换模式前处理未保存编辑，结束后回到稳定的作业位置。

## 案例：数量编辑与离线作业

仓库管理员在同一订单中处理多项物料。页面既要支持快速修改数量，也要说明当前是否处于离线模式，以及操作结果是否已确认。

以下按[最终操作视频](/docs/solutions/hac/principles/goals-scenarios#操作流程与效果)说明入口和结果：

| 操作 | Demo 中的结果 |
| --- | --- |
| 点击订单扫码入口 | 打开“准备就绪，请按扫码键”的等待界面，提供取消入口 |
| 点击物料数量 | 打开带当前物料信息的数量面板 |
| 调整数值并点击“保存修改” | 面板关闭，原卡片数量从 `50/100` 更新为 `55/100` |
| 点击“接收货品” | `0/100` 的物料提示不足；另一项已为 `100/100` 的物料提示已完成 |
| 确认切换离线模式 | 页面显示“离线模式”，可继续打开数量面板 |
| 离线修改数量并切回在线 | 数量从 `0/100` 保存为 `10/100`；切回在线后显示同步成功提示 |

“保存修改”和“接收货品”是两个独立动作。页面数量回显不等于业务接收完成，具体保存与接收规则在下方预留补充。

## 异常时如何继续

- **数量或物料不符合规则：** 保留当前内容，提示修改、重扫或联系处理人员。
- **正在保存或结果不确定：** 防止重复业务提交，核对结果后再继续；合法的重复扫码累计按业务规则处理。
- **网络中断或同步失败：** 按离线范围保留记录，提供恢复入口；“在线模式”不等于实际网络始终可用。
