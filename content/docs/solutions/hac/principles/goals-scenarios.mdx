PDA 页面以**简洁、实用、操作清楚**为目标。先明确谁在什么环境下完成什么工作，再决定页面需要展示哪些信息、提供哪些操作。

## 设计原则与最佳实践

1. **围绕任务设计。** 每个页面解决一个主要问题，优先展示当前订单、物料、数量和下一步操作。
2. **界面简洁易读。** 用清楚的分组、文字和按钮组织内容，减少装饰、复杂布局和无关信息。
3. **操作直接。** 通过筛选、扫码和数量加减减少手工输入，在当前订单内完成物料处理，减少页面往返。
4. **结果明确。** 保存后更新数量，异常说明原因；状态配合文字和图标，不能只靠颜色区分。
5. **适应现场网络。** 弱网时保留输入，无信号时支持约定范围内的离线录入，恢复在线后同步并反馈结果。

## 案例：工厂仓库采购入库

某工厂位于偏远园区，仓库管理员需要在卸货区和库位之间核对供应商送来的物料。现场使用 PDA 作业，移动网络信号较弱，部分位置无信号。

管理员的任务是：**选择采购订单 → 核对物料 → 录入数量 → 检查接收结果 → 继续下一项**。采购审批、供应商维护和财务处理不放入这条现场流程。

这意味着页面既要方便查找和录入，也要支持离线数量记录，避免管理员为了网络连接反复离开作业位置。以下用这个模拟场景解释 Demo 的设计。

## 从场景到页面设计

| 场景需要 | 采用的设计做法 | Demo 中的效果 |
| --- | --- | --- |
| 管理员进入应用后快速找到工作 | 首页保留明确的业务入口 | 点击“采购入库”进入订单列表 |
| 多张订单中找到当前任务 | 用状态筛选和搜索缩小范围 | “全部 / 待收货 / 部分收货 / 已完成”标签及扫码入口 |
| 小屏上核对物料并修改数量 | 简单卡片分组，数量集中展示，点击后编辑 | 物料卡片、数量加减和“保存修改”按钮 |
| 判断操作是否满足接收条件 | 数量回显，异常和完成都有明确提示 | 数量不足提示、已完成物料提示 |
| 无信号区域仍需记录数量 | 在同一作业页切换模式，恢复在线后同步 | 离线模式修改数量，切回在线后显示同步成功 |

这些页面使用一致的布局、少量状态颜色和明确按钮，让管理员能看清当前对象并直接操作。

## 操作流程与效果

下面是最终视频中的主要操作：

1. **登录并选择订单。** 登录后进入采购入库，切换订单状态筛选，打开扫码等待界面，随后进入订单详情。
2. **在线修改数量。** 将一项物料的数量从 `50/100` 调整为 `55/100`，点击“保存修改”，原卡片显示更新后的数量。
3. **查看接收结果。** 点击“接收货品”，数量为 `0/100` 的物料提示不足；另一项已为 `100/100` 的物料显示已完成提示。
4. **离线录入并同步。** 确认切换到离线模式，将数量为 `0/100` 的物料调整并保存为 `10/100`；切回在线后出现“同步物料Quantity数据成功！”提示，数量仍显示为 `10/100`。
