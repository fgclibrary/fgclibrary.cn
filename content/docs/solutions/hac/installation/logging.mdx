HAC 日志用于排查容器运行、设备能力调用、扫码、定位、拍摄、文件和兼容性问题。它主要反映 HAC 容器及其与 Android 能力之间的调用过程，不能替代页面 DevTools、服务器日志或 PDA 厂商工具。日常使用不建议长期打开详细日志，以免影响性能和占用存储。

## 日志位置

日志默认保存在设备 `Download` / `Downloads` 文件夹中，具体位置可能因 Android 版本、设备厂商策略或 HAC 版本而不同。

![hac日志](/images/hac/logs_hac_2.webp)

文件名通常类似以下示例，实际名称可能因版本而不同：

```text
HAC_Log_ERROR_20240112.txt
```

日志按天拆分，默认保留最近 `7` 天。反馈问题时，优先收集问题发生当天的文件；跨天复现时同时收集相邻日期日志。日志日期以设备时间为准，设备时间或时区不准确时，应在反馈信息中说明。

## 日志级别

| 级别 | 用途 |
| --- | --- |
| `error` | 默认级别，只记录错误和异常 |
| `verbose` | 诊断级别，记录更详细的运行过程 |

只有在配合排查问题时，才临时启用 `verbose`。

一般运行异常可先查看 `error` 日志；问题无法稳定复现、需要了解调用过程，或需要确认命令是否到达 HAC 时，再临时启用 `verbose`。详细日志可能包含更多设备信息、请求信息或错误堆栈，采集后应及时关闭。

## 启用诊断日志

在 HAC 设置页勾选“启用全部诊断日志”。

![启用verbose日志](/images/hac/logs_hac_1.webp)

<Callout type="warn" title="需要重启">
日志策略通常需要关闭或强制停止 HAC 进程后重新启动才会生效，具体操作以设备系统界面为准。问题排查结束后，应关闭诊断日志并再次重启 HAC。
</Callout>
## 标准采集流程

按以下流程收集日志，可以让日志时间与问题现象对应起来：

```text
记录问题发生时间和设备时区
-> 记录预期结果、实际结果和最短复现步骤
-> 根据问题需要临时开启 verbose
-> 重启 HAC，使日志设置生效
-> 使用相同账号、数据和网络环境复现一次
-> 记录实际复现时间和操作结果
-> 导出复现时段对应的日志文件
-> 关闭 verbose，并再次重启 HAC
```

不需要 `verbose` 时，可以直接使用当前的 `error` 日志采集。复现前应先确认旧日志的日期和文件名，不要把旧日志与本次复现日志混在一起。

## 阅读和筛选日志

1. 先根据设备时间和复现时间定位日志范围，再查看该时间点前后的上下文。
2. 优先关注最早出现的 `ERROR`、`Exception`、权限失败、超时和命令返回失败；后续错误可能是连锁结果。
3. 涉及设备能力时，可结合能力名称、命令名称和错误信息筛选，具体字段以当前 HAC 版本的日志为准。
4. 不要仅凭单条错误判断根因，应结合复现步骤、页面现象、命令返回值和其他层级的日志进行确认。

## 转存日志

可选方式：

- 设备文件管理器中打开 `Download` 文件夹，复制日志；
- 使用 USB 数据线传到电脑；
- 使用蓝牙、企业文件传输工具或内部工单附件上传；
- 在设备上用文本查看器直接打开。

如果需要收集多天日志，请保留原始文件名，并在反馈中标明设备、日期和复现时间，避免不同设备的同名文件被覆盖。日志中可能包含 URL、设备信息、文件路径、错误堆栈或业务数据，转存和上传前应按项目要求进行脱敏，并通过授权的内部渠道传递。

## 日志文件异常

| 现象 | 检查和处理 |
| --- | --- |
| 找不到日志文件 | 确认 HAC 已实际运行，并检查正确的 `Download` / `Downloads` 目录；如果需要 `verbose` 日志，再确认已开启诊断日志并重启 HAC，同时检查设备时间和存储空间 |
| 日志文件为空 | 确认已经实际复现问题；如果需要更详细的调用过程，临时开启 `verbose` 并重启 HAC 后再复现 |
| 日志没有新内容 | 记录复现时间，确认查看的是当前设备和当天文件；再次确认 HAC 进程已按要求重启 |
| 日志过大或跨越多天 | 按复现时间筛选相关文件和上下文，不要直接提交与问题无关的全部日志 |

## 问题反馈清单

提交给开发或支持人员时，建议同时提供：

- 问题发生时间；
- 设备时间和时区；
- 预期结果、实际结果和复现频率；
- 复现步骤；
- 设备型号；
- Android 版本；
- WebView 版本；
- HAC 版本；
- 活字格应用版本、插件版本和相关配置说明（如适用）；
- 网络环境，以及是否使用 VPN 或代理（如适用）；
- 当天 HAC 日志；
- 如涉及页面异常，附 DevTools Console / Network 关键错误；
- 如涉及设备能力，附设备截图或录屏，以及厂商测试工具结果（如适用）。

提交前请对请求参数、响应内容、Cookie、日志和截图进行脱敏，不要提供密码、访问令牌、配置二维码或无关的个人与业务数据。

## 排查建议

| 现象 | 建议 |
| --- | --- |
| 页面按钮无响应 | 先看 DevTools `Console`，再看 HAC 日志中的本地能力调用异常 |
| 扫码结果没有写入 | 检查扫码广播配置、页面监听逻辑和 HAC 扫码日志 |
| 拍照、定位、文件失败 | 检查 Android 权限、命令返回值和 HAC 异常堆栈 |
| 只在某台 PDA 出现 | 对比设备型号、系统、WebView、HAC 版本和厂商配置 |

排查时应先确定问题所在层级：页面脚本或布局优先查看 DevTools，接口响应结合 Network 和服务器日志，HAC 桥接和 Android 权限查看 HAC 日志及设备设置，扫码头、定位模块等硬件问题还需结合 PDA 厂商工具。HAC 日志没有记录时，不代表页面或硬件一定没有问题，仍应按对应层级继续确认。

## 采集完成检查

- 日志中包含本次复现时间点及前后必要上下文；
- 日志文件、设备型号、HAC 版本和复现步骤能够相互对应；
- 已关闭 `verbose`，并按要求重启 HAC；
- 已删除设备或电脑上的临时日志副本，并完成敏感信息脱敏。

页面运行时调试请参考[调试 HAC](/docs/solutions/hac/installation/debugging)。
