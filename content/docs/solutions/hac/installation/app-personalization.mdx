## 适用场景

个性化配置用于调整 `HAC` 的 ActionBar（APP 顶部区域）、菜单入口、颜色和扫描头参数。它适合首次部署、品牌适配、现场设备配置和管理员运维。

这些配置会保存到设备本地，通常在卸载应用前长期有效。不要把配置命令放进普通高频业务流程。由于配置可能触发 APP 重新加载，本页属于安装、部署和调试阶段的配置说明。

## 使用前提

- 应用运行在 `HAC` 中；
- 已安装提供个性化配置命令的插件；
- 当前用户具备管理员或运维权限；
- 执行配置前已保存当前业务状态；
- 已确认 HAC 版本、Android 版本、PDA 型号和厂商程序支持对应能力；
- 项目有恢复配置的方式，例如快速设置二维码或管理员入口；

按配置内容追加确认：

- 配置扫描头参数时，扫描头参数已和目标 PDA 厂商配置确认一致，并已准备扫码测试页和最小验证数据；
- 配置帮助或关于菜单时，对应 URL 在目标设备网络中可访问；
- 批量部署时，已准备目标环境、设备型号和配置版本记录。

> 待补充：项目使用的个性化配置插件名称、版本要求，以及快速设置二维码的生成入口和恢复入口。

## 命令速查

| 能力 | 命令 | 类型 | 输入 / 输出 |
| --- | --- | --- | --- |
| 顶部区域 | 配置APP的ActionBar | 普通 | 是否显示、颜色、配置菜单、帮助页、关于页 |
| 菜单入口 | 配置APP的菜单 | 普通 | 配置菜单、帮助页、关于页 |
| 扫描头 | 配置扫描头参数 | 普通 | 广播名称（Action）、广播键值（Extra） |
| 顶部颜色 | 配置APP的ActionBar颜色 | 普通 | RGB 颜色，格式为 `FFFFFF` |
| 顶部颜色 | 读取ActionBar颜色 | 同步或异步，按插件实现为准 | 输出 `FFFFFF` 格式 RGB |
| 顶部颜色 | 读取ActionBar颜色到单元格 | 同步或异步，按插件实现为准 | 输出到指定单元格 |

<Callout type="warn" title="配置会重新加载">
配置 ActionBar、菜单或颜色后，APP 可能重新加载。不要在这些命令后继续串联业务命令；应等待 APP 恢复并重新验证配置。
</Callout>
## 配置前确认

先根据目标选择命令，不要为了修改一个字段重复覆盖整组配置：

| 目标 | 使用命令 | 需要确认的结果 |
| --- | --- | --- |
| 同时修改 ActionBar 显示、颜色和菜单 | 配置APP的ActionBar | ActionBar、配置菜单、帮助页和关于页均符合预期 |
| 只修改菜单入口 | 配置APP的菜单 | 菜单显示状态和页面地址符合预期，其他 ActionBar 状态未被误改 |
| 只修改顶部颜色 | 配置APP的ActionBar颜色 | 颜色生效，其他配置保持不变 |
| 查看当前颜色 | 读取ActionBar颜色 | 返回 `FFFFFF` 格式 RGB |
| 将当前颜色写入表格 | 读取ActionBar颜色到单元格 | 目标单元格得到颜色值 |
| 修改扫码头接收参数 | 配置扫描头参数 | HAC 页面实际收到并正确解析扫描结果 |

> 待补充：请确认“配置APP的菜单”和“配置APP的ActionBar颜色”是否会保留其他未填写字段的原值，还是会覆盖整组配置。

## 推荐流程

首次部署和配置：

```text
确认设备型号、HAC 版本和目标环境
-> 保存当前配置和业务状态
-> 进入管理员配置页
-> 回显当前配置
-> 用户确认顶部区域、颜色、菜单和 URL
-> 提示 APP 将重新加载
-> 执行配置命令
-> 等待 APP 重载完成
-> 验证顶部区域、菜单和关键页面
```

“回显当前配置”目前仅适用于已有读取命令的字段。当前文档明确支持读取 ActionBar 颜色；ActionBar 显示状态、菜单状态、帮助页地址、关于页地址和扫描头参数需要通过项目保存的配置记录或人工确认。

扫描头参数配置：

```text
确认 PDA 厂商和型号
-> 在设备系统或厂商程序中开启广播 / Intent
-> 确认 Action 和 Extra key
-> 执行【配置扫描头参数】
-> 进入扫码测试页
-> 验证持续扫码或单次扫码结果
-> 确认 HAC 页面收到完整码值并完成业务解析
-> 记录设备和配置版本
```

配置异常恢复：

```text
确认当前 APP 无待提交业务
-> 进入【待补充：快速设置二维码或管理员恢复入口】
-> 使用已验证的配置二维码或管理员恢复流程
-> 恢复 ActionBar、菜单、颜色和扫描参数
-> 等待 APP 重载
-> 重新进入扫码和最小业务测试页
-> 验证配置已保存
```

> 待补充：隐藏配置菜单后，设备上实际进入快速设置或管理员恢复的操作步骤；如果不同设备步骤不同，请按设备型号分别列出。

## 配置 ActionBar

【配置APP的ActionBar】用于一次设置 ActionBar（APP 顶部区域）是否显示、顶部区域颜色、【配置】菜单是否显示，以及【帮助】和【关于】页面。

| 参数 | 说明 | 配置建议 |
| --- | --- | --- |
| 是否显示 ActionBar（APP 顶部区域） | 控制 APP 顶部区域是否显示 | 隐藏前确认仍有恢复配置的入口 |
| ActionBar 颜色 | RGB 颜色，格式为 `FFFFFF` | 选择与文字有足够对比度的颜色 |
| 菜单：是否显示【配置】 | 控制配置入口是否显示 | 生产环境隐藏前保留快速设置或管理员恢复方式 |
| 菜单：【帮助】页面 | 帮助页面地址 | 使用完整 `https://` 地址并在 PDA 网络验证 |
| 菜单：【关于】页面 | 关于页面地址 | 使用完整 `https://` 地址并确认登录态和证书 |

配置完成后 APP 可能重新加载。返回页面后应检查顶部区域、配置菜单、帮助和关于页面是否符合目标环境。

## 配置 APP 菜单

【配置APP的菜单】用于设置菜单入口，字段与 ActionBar 配置中的菜单字段相同：配置菜单的显示状态、帮助页面和关于页面地址。

适合只调整菜单而不改变顶部区域其他设置的场景。隐藏配置菜单前，必须确认管理员仍能通过快速设置二维码、设备管理工具或其他恢复流程重新配置。

## 配置扫描头参数

【配置扫描头参数】用于设置 PDA 扫描服务向 HAC 发送结果时使用的广播参数：

| 参数 | Android 对应概念 | 说明 |
| --- | --- | --- |
| 广播名称（Action） | Intent Action | 必须与设备厂商扫描服务的 Action 一致 |
| 广播键值（Extra） | Intent Extra key | 必须与厂商发送码值的 key 一致 |

配置前先在 PDA 厂商工具中确认广播 / `Intent` 模式、Action、Extra key、码值前后缀和分隔符。配置完成后必须在目标机型上用物理扫码键或厂商测试工具验证结果。


## 配置和读取 ActionBar 颜色

【配置APP的ActionBar颜色】单独设置顶部区域颜色，颜色格式为不带 `#` 的六位 RGB 值，例如 `FFFFFF`。设置后 APP 可能重新加载。

【读取ActionBar颜色】返回当前颜色，结果为 `FFFFFF` 格式 RGB；【读取ActionBar颜色到单元格】将结果写入指定单元格。读取命令适合配置页回显、部署记录和避免重复设置。

## 设计要点

- 配置入口放在管理员或运维页面；
- 配置前保存业务状态，并提示 APP 可能重新加载；
- 配置命令后不要立即串联依赖旧页面状态的业务命令；
- 隐藏“配置”菜单前，必须确认还有恢复配置的方式；
- 帮助和关于菜单 URL 使用完整 `https://` 地址，并在设备网络中验证；
- ActionBar 颜色用于区分客户、环境或应用类型时，要保证文字对比度；
- 读取 ActionBar 颜色可用于配置页回显，避免重复设置；
- 扫描头参数配置完成后，必须提供扫码测试入口；
- 同一项目的测试、预生产和生产配置应分别保存，避免二维码和设备参数混用；
- 配置记录中保存设备型号、HAC 版本、配置时间和操作者，便于恢复和排查；
- 批量部署前先在每种目标机型上完成配置、重载和页面扫码验证。

## 异常处理

| 异常 | 常见原因 | 推荐处理 |
| --- | --- | --- |
| 配置后后续命令未执行 | APP 重载 | 不在配置命令后串联业务命令，等待重载后重新进入页面 |
| 配置后顶部区域或菜单未变化 | 配置未保存、字段值无效或页面仍显示旧状态 | 重启 HAC，重新读取颜色和检查菜单；记录配置值 |
| 配置菜单隐藏后无法修改 | 缺少恢复入口 | 使用快速设置二维码或管理员恢复流程 |
| 帮助 / 关于打不开 | URL 不完整、网络不可达、证书或登录态问题 | 使用完整 URL，并在 PDA 网络下验证 |
| 颜色显示异常 | 格式错误、包含 `#`、颜色值无效或对比度不足 | 使用六位 RGB，检查亮暗背景和文字对比度 |
| 扫描头命令无结果 | 设备广播和 HAC 配置不一致、扫描服务未启动 | 重新核对 Action、Extra key、前后缀和厂商设置 |
| 扫描结果带前后缀或分隔符 | 设备系统预处理 | 记录原始码值，和厂商确认输出配置 |
| 不同设备表现不一致 | 厂商系统、扫描服务或 HAC 版本差异 | 记录设备型号和版本并逐机型验证 |
| 配置二维码或恢复入口无效 | 配置版本错误、二维码损坏或相机权限不足 | 重新生成配置码，授权相机并在测试设备验证 |

## 配置记录与回退

每次配置应记录目标环境、设备型号、HAC / Android / WebView / 插件版本、配置前后的参数、操作者、时间和验证结果。配置二维码或其他批量配置文件应带有环境和版本标识，避免测试配置误用于生产设备。

升级、覆盖安装或重新导入配置前，先确认没有待提交业务，并保存当前配置记录。配置异常时，按“恢复配置入口 → 重新导入已验证配置 → 等待 APP 重载 → 验证 ActionBar、菜单和扫码”的顺序回退；只有在确认本地配置和业务数据已处理后，才考虑卸载重装。

> 待补充：项目配置记录的保存位置、配置版本命名规则、回退负责人和回退完成判定。

## 兼容性与安全边界

- 在项目记录中保存 HAC、Android、WebView、插件、PDA 型号和厂商扫描服务版本；
- 同一厂商不同型号可能使用不同 Action、Extra key 和默认扫描模式，不能只按品牌判断；
- 配置命令依赖 HAC 原生能力，普通浏览器中应隐藏入口或提示切换环境；
- 帮助、关于页面和配置二维码可能包含项目地址或环境信息，应限制访问和传递范围；
- 生产环境隐藏配置入口时，应保留受控恢复方式，并限制管理员权限；
- 扫描参数、菜单 URL 和颜色配置应在测试设备验证通过后再批量部署。

## 验收标准

1. 配置页面只能由管理员或运维用户访问，执行前会保存业务状态并提示 APP 可能重载。
2. ActionBar 显示状态、配置菜单、帮助页和关于页与目标环境要求一致。
3. 配置或读取的颜色使用六位 RGB 格式，顶部文字和背景保持可读对比度。
4. 配置扫描头后，目标 PDA 的扫描键或厂商工具能发出测试码值，且 HAC 页面实际收到完整码值并能处理成功、重复、无效和无结果。
5. 配置命令触发 APP 重载后，页面不会继续执行依赖旧状态的业务命令。
6. 隐藏配置菜单后，快速设置二维码或管理员恢复流程仍然可用。
7. HAC 重启后配置仍然保留，且测试、生产环境的配置记录可以追溯到设备、版本、时间和操作者。
8. 配置异常时能够使用已验证的二维码或管理员入口恢复，不需要通过卸载应用清除配置。
