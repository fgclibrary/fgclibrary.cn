## 功能页的阅读顺序

每个功能页尽量使用同一套结构：

1. **适用场景**：判断设备能力是否适合当前任务；
2. **使用前提**：确认 HAC、插件、权限、硬件和系统配置；
3. **命令速查**：找到命令用途和返回结果；
4. **推荐流程**：明确触发、焦点、成功反馈和下一步；
5. **设计要点**：处理生命周期、状态、重复操作和安全边界；
6. **异常处理**：提供重试、重扫、手动修正或备用流程。

## 通用边界

- 持续扫码、广播接收、BLE 订阅和物理按键监听离开页面时必须停止；
- 页面必须区分“本地已保存”“待补传”和“已提交到服务端”；
- 配置类操作放在运维或管理员入口，普通操作员只看到业务流程；
- 普通浏览器无法调用 HAC 的 Android 能力，应隐藏入口或明确提示运行环境。

完整业务流程可参考[典型解决方案](/docs/solutions/hac)；页面布局、触控和性能原则见[原则与最佳实践](/docs/solutions/hac/principles)。
