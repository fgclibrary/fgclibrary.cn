## 适用场景

扫描用于在 `HAC` 中接收 PDA 扫描头或 UHF 读卡器返回的结果，并交给活字格页面继续校验、匹配和提交。

| 能力 | 适合场景 | 关键风险 |
| --- | --- | --- |
| 激光 / 二维扫码 | 收货、盘点、拣货、复核、报工 | 扫错码、重复扫码、结果带前后缀 |
| UHF / RFID | 托盘识别、资产巡检、批量盘点 | 一次读到多个 EPC、读距不稳定、环境干扰 |

UHF 不是“更远的扫码”。它可能一次返回多个标签，页面必须支持拆分、去重、匹配和异常展示。

## 使用前提

- 应用运行在 `HAC` 中；
- PDA 带有激光 / 二维扫描头，或 UHF / RFID 模块；
- 设备扫描模式已设置为“广播”或 `Intent`；
- HAC 中“扫描头配置”或“UHF 配置”和设备侧 Action、Extra key 一致；
- 页面已定义成功、为空、重复、不匹配、设备未配置时的处理方式。

<Callout type="warn" title="先查配置">
扫描结果异常时，优先检查设备系统配置和 HAC 配置是否一致。很多 PDA 会在系统层处理前后缀、回车、编码和分隔符。
</Callout>
## 命令速查

| 命令 | 类型 | 用途 |
| --- | --- | --- |
| 【开始持续扫码】 | 异步 | 连续接收激光 / 二维扫码结果 |
| 【停止持续扫码】 | 普通或同步 | 停止连续接收扫码结果 |
| 【单次扫码】 | 异步 | 发起一次扫码并返回结果 |
| 【开始接收UHF扫描结果】 | 异步 | 连续接收 UHF / RFID 读卡结果 |
| 【停止接收UHF扫描结果】 | 普通或同步 | 停止接收 UHF 结果 |

持续类命令适合高频作业页；单次扫码适合低频确认、绑定设备或选择单据。

## 推荐流程

连续扫码：

```text
进入作业页
-> 执行【开始持续扫码】
-> 用户按下扫码键
-> 页面接收码值
-> 校验是否属于当前任务
-> 成功：写入明细并等待下一次扫码
-> 失败：保留码值并提示原因
-> 离开页面时执行【停止持续扫码】
```

单次扫码：

```text
点击“扫码”
-> 执行【单次扫码】
-> 返回码值
-> 写入变量或单元格
-> 校验业务规则
-> 成功进入下一步，失败允许重扫
```

UHF：

```text
进入 UHF 作业页
-> 执行【开始接收UHF扫描结果】
-> 用户按下读卡键
-> 接收一个或多个 EPC
-> 拆分、去重、匹配业务对象
-> 展示已匹配、未匹配、重复项
-> 提交或清空重读
-> 离开页面时执行【停止接收UHF扫描结果】
```

## 设计要点

- 顶部明确当前任务、单据、库位、工位或批次；
- 扫码区显示等待、成功、失败、重复、不匹配等状态；
- 保留原始码值，便于排查设备前后缀和编码问题；
- 高频扫码成功后自动准备下一次操作，减少手动点击；
- UHF 页面不要只放一个输入框，应显示本次 EPC 列表、数量、匹配结果和异常原因；
- 打开弹窗、拍照、签名、切换页面或任务结束时，必须停止持续接收。

## 异常处理

| 异常 | 常见原因 | 推荐处理 |
| --- | --- | --- |
| 按扫码键无反应 | 设备模式不对、HAC 配置不匹配、未启动持续扫码 | 提示检查广播 / Intent 配置，并允许重新启动 |
| 扫码结果为空 | 条码损坏、距离不合适、扫描头未读到 | 保留页面状态，提示重新扫描 |
| 结果带前后缀 | 设备系统预处理 | 记录原始码值，和厂商确认配置 |
| 重复扫码 | 连续按键或设备重复上报 | 按业务键去重，并提示已扫描 |
| 条码不匹配 | 扫错物料、箱号、任务 | 显示当前码值和不匹配原因 |
| UHF 一次读到多个 EPC | 读距过远或附近标签较多 | 展示列表，允许清空、去重、提交匹配项 |
| UHF 读不到标签 | 标签方向、距离、金属环境、功率设置 | 提示调整位置或检查设备功率 |
